# The app (`Sources/ScreencastDirector`)

- `App.swift` is the SwiftUI `App` (main `Window`, `Settings` tabs, `MenuBarExtra`, menu commands); `AppDelegate` (via `NSApplicationDelegateAdaptor`) holds the models and runs recording. `NSApp.delegate` is SwiftUI's own object, so code reaches ours through `AppDelegate.shared`. ScreenCaptureKit recorder (sample buffers use the host clock, same as `InputTap`'s `CLOCK_UPTIME_RAW`), library, preview, and the Claude box.
- View state lives in `ObservableObject`s (no `@State` without Xcode's macros).
- The Claude box runs `claude -p --permission-mode acceptEdits` with the arguments in `DirectorCore/ClaudeEdit.swift` (checked by test.sh): `Read(./**)`, `Edit(./plan.json)` and `director describe`/`still`/`review`/`validate`/`profiles`/`profile .`/`template . freeze|update` allowed, never `add` (it copies any file into the project, where Read reaches it) or `template save` (it writes the shared library); `SD_ONLY_PROJECT` in its environment makes director refuse any other folder, since allow rules match prefixes; Write and `.claude/` denied, and `--setting-sources ""` so no settings load: not a project folder's `.claude/` hooks, nor the user's own allow rules. A follow-up ask resumes the last ask's session (`ProjectModel.claudeSession`, dropped after a failed ask); when an ask finishes, the problems `PlanCheck` finds that weren't there before are added to its reply. `AIText` runs `claude -p` with `--tools ""` from an empty temp folder. AI edits pass through `PathSafety.sanitize`, which undoes file paths (recording, camera, music, logos, fonts) pointed outside the project and the user's support folder (saved profiles keep their assets there).
- AI providers (`AI.swift`): Claude Code CLI (agentic), the Anthropic Messages API (raw HTTP, since Swift has no SDK; `fallbacks: "default"` with `server-side-fallback-2026-07-01`), or any OpenAI-compatible endpoint. API edits return the complete plan in a json code block, which is parsed, normalized and applied through `apply`, so it can be undone.
- Claude's Edit tool writes `plan.json` in place, which a folder watch misses; the app polls the file's modification date instead.
- Bindings into the plan's arrays (`zooms[i]`) must be bounds-checked (`bindItem` in Inspector.swift): after an undo or delete removes the selected item, SwiftUI can read the old binding once before redrawing, and an out-of-range index kills the app. `commit()` clears a stale selection before publishing the plan for the same reason.
- Editor shortcuts live in `Shortcuts.swift` (defaults match Screen Studio's so the same muscle memory works). A local key monitor in AppDelegate dispatches them and lets keys through while a text field has focus.
- Recording UI (`RecordingHUD.swift`, `RecordSetup.swift`): the widget, countdown and New Recording panel are `FloatingPanel`s with `sharingType = .none`, so they never appear in recordings, and screenshots can't see them either. Launch with `-panelsInScreenshots YES` to capture them. Size a panel with `NSHostingController.sizeThatFits` (`FloatingPanel.host`): an `NSHostingView`'s `fittingSize` is zero before it's in a window, which makes a 0×0 invisible panel.
- Errors and confirmations go through `Notices.shared` (a banner in the main window), and prompts use `presentAlert` (a sheet on the main window). Don't add `runModal()` alerts.
- A SwiftUI `Form` in an `NSWindow` built with `contentRect: .zero` collapses to its title bar. Give the window and the view a real size.

## Seeing and driving the UI

- `macos/app-shot.sh <project-dir> <out.png> [--no-build] [-- <app arguments>]` launches the dist/ build on a temp copy of a project, brings its window forward and captures it (`axpress <pid> window-id`). Window screenshots (`screencapture -l`) of a window on another Space show the player black, which is why it brings the window forward first.
- Driving the UI in tests: timeline bars are accessibility buttons (ordered by position, not by track), so System Events `perform action "AXPress"` selects them; `perform action "AXIncrement"` moves a slider (setting `value` doesn't reach the SwiftUI binding). Always `set frontmost to true` and check it before `keystroke`, or the keys go to whatever app is in front. Use `key code 44` for ⌘/, since `keystroke "/"` is layout-dependent.
- SwiftUI buttons here have no AX title, and timeline bars have no description either. Find inspector and popover buttons by their `.help` text (give a button one if a test needs it) or a timeline chip by its `accessibilityLabel`, and press them with `Tests/AXPress.swift` (`"$AXPRESS" "$PID" help|description <text>`), which walks the test instance by PID. Don't walk AppleScript's `entire contents`: its references name the process, not the PID, so with the installed copy running they reach that copy and fail silently inside `try`. Find a bar by pressing each and reading the inspector. `AXPress` also focuses or reads a text field by placeholder (`focus-field "Ask *"` is the Claude box) and sends a real click to the title bar (`click-title`).
- `smoke-test.sh` builds dist/, launches that copy on a temp fixture (`-projectsFolder`, `-openProject`), and drives the editor through System Events by PID; it needs a GUI session, so it's local only. It runs AI edits against a stand-in Claude: the app takes `-claudePath <file>` (with `-ai.provider claudeCode`), and the script's stand-in fails like a signed-out Claude or hangs until stopped. The first ask on a recording takes about 10 s to start (screen text is read first). Typing on the Mac while it runs lands in the test instance's Claude box.
- AppleScript `keystroke ","` and `"/"` can map to other keys on non-US keyboard layouts (`","` opened the import panel). Use `key code` or click menu items; the app menu is `menu bar item 2`.

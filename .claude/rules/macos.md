# Swift engine and app (`macos/`)

- `Sources/DirectorCore`: the plan model, mapping and smoothing math (Timeline.swift), draft plan rules (Planner.swift: speech 1x, typing 3x, mouse 1.5x, screen motion 4x, idle and filler words cut, zooms from click/typing clusters; `Rules` holds the thresholds), the readable timeline (Describe.swift), native analysis (motion from decoded frames, whisper-cli → mlx-style transcript.json) and the renderer: `Scene` draws a frame with Core Image + CoreText, `Composition` builds the AVComposition (cuts and speed as edits, muting and fades in an audio mix) with a custom compositor. The same composition feeds the preview player and the export.
- The camera eases asymmetrically (`cameraAt(lead:tail:)`: zooms start 0.3 s early with a 1.6x ease-out tail), with motion blur during moves; word timings snap to loudness at load (`WordTiming`).
- `Sources/director`: CLI (`analyze`, `plan`, `describe`, `render`, `still`, `debug`). The app bundles it, and `Resources/edit-prompt.md` tells headless Claude to use it (`{{DIRECTOR}}` is replaced with its path).
- `Sources/ScreencastDirector`: the app. `App.swift` is the SwiftUI `App` (main `Window`, `Settings` tabs, `MenuBarExtra`, menu commands); `AppDelegate` (via `NSApplicationDelegateAdaptor`) holds the models and runs recording. `NSApp.delegate` is SwiftUI's own object, so code reaches ours through `AppDelegate.shared`. ScreenCaptureKit recorder (sample buffers use the host clock, same as `InputTap`'s `CLOCK_UPTIME_RAW`), library, preview, and the Claude box (`claude -p --permission-mode acceptEdits` with `Read(./**)`, `Edit(./plan.json)` and `director describe`/`still`/`review` allowed, Write and `.claude/` denied, and `--setting-sources user` so a project folder's `.claude/` settings and hooks never load; `AIText` runs `claude -p` with `--tools ""` from an empty temp folder). AI edits pass through `PathSafety.sanitize`, which undoes file paths (recording, camera, music, logos, fonts) pointed outside the project.
- Command Line Tools only, so no SwiftUI macros (`@State`): view state lives in `ObservableObject`s.
- SourceKit reports "Cannot find type ... in scope" on single files; ignore it and trust `swift build`.
- An `AVAssetTrack` does not keep its `AVURLAsset` alive. Inserting from a track whose asset was freed fails with the unhelpful -11800/-12780; keep the asset in scope (see `camAsset` in Composition.swift).
- Claude's Edit tool writes `plan.json` in place, which a folder watch misses; the app polls the file's modification date instead.
- Editor actions (`DirectorCore/EditorActions.swift`): `Selection` and `TimelineSelection` (click and drag-box rules), and the plan edits behind the timeline, keyboard and transcript (delete, group moves, clip speed, zoom nudge and duplicate, marker jumps, word selection, the AI ask's context). `ProjectModel` keeps the app state (published selection, playhead, undo, status) and calls these, so `test.sh` checks them (`Tests/ChecksEditor.swift`). Put new plan logic for an editor action there, not in ProjectModel.
- Bindings into the plan's arrays (`zooms[i]`) must be bounds-checked (`bindItem` in Inspector.swift): after an undo or delete removes the selected item, SwiftUI can read the old binding once before redrawing, and an out-of-range index kills the app. `commit()` clears a stale selection before publishing the plan for the same reason.
- Editor shortcuts live in `Shortcuts.swift` (defaults match Screen Studio's so the same muscle memory works). A local key monitor in AppDelegate dispatches them and lets keys through while a text field has focus.
- Profiles (`DirectorCore/Look.swift`, `Formats.swift`): `plan.look` holds fonts, colors, the bracket frame and the watermark; `style.screenAspect` crops the screen for vertical, square and feed formats, and `Scene.screenMap` pans the crop to the camera focus (the last click when there's no zoom).
- AI providers (`ScreencastDirector/AI.swift`): Claude Code CLI (agentic), the Anthropic Messages API (raw HTTP, since Swift has no SDK; `fallbacks: "default"` with `server-side-fallback-2026-07-01`), or any OpenAI-compatible endpoint. API edits return the complete plan in a json code block, which is parsed, normalized and applied through `apply`, so it can be undone.
- Lip sync (`DirectorCore/LipSync.swift`): the recorder's `camera.offset` comes from first-frame timestamps, which webcams can stamp hundreds of ms late. `LipSync.measure` correlates Vision inner-lip opening with voice level in four 30 s speech windows, searching only ±0.5 s around the current offset (speech rhythm repeats the correlation about every 0.7 s). It runs in `analyzeAndPlan`, `director sync-camera` and Camera > Lip sync.
- Publishing (`DirectorCore/Publish.swift`): the SRT uses the same caption pages as the burned-in captions. Thumbnails score camera frames with `VNDetectFaceCaptureQualityRequest` plus `CIDetector` smile and blink detection, and cut the person out with `VNGeneratePersonSegmentationRequest`.
- Recording UI (`RecordingHUD.swift`, `RecordSetup.swift`): the widget, countdown and New Recording panel are `FloatingPanel`s with `sharingType = .none`, so they never appear in recordings, and screenshots can't see them either. Launch with `-panelsInScreenshots YES` to capture them. Size a panel with `NSHostingController.sizeThatFits` (`FloatingPanel.host`): an `NSHostingView`'s `fittingSize` is zero before it's in a window, which makes a 0×0 invisible panel.
- Pausing doesn't stop the writer: the paused stretch is recorded, saved as `source.json` `pauses` (source seconds), cut by the planner, and kept cut by `retrimPauses(paused:)`. `InputTap.paused` stops input logging meanwhile.
- Errors and confirmations go through `Notices.shared` (a banner in the main window), and prompts use `presentAlert` (a sheet on the main window). Don't add `runModal()` alerts.
- A SwiftUI `Form` in an `NSWindow` built with `contentRect: .zero` collapses to its title bar. Give the window and the view a real size.
- Window screenshots (`screencapture -l`) of a window on another Space show the player black. Bring the window forward before judging the preview.
- `logger/main.swift` (event tap) and `logger/InputEvents.swift` (what each event logs, checked by `test/logger-test.sh` with synthetic events and read back through DirectorCore): input logger. Timestamps use `CLOCK_UPTIME_RAW`, the clock AVFoundation stamps frames with; `sd record` reads the first frame's time from ffmpeg's log (`start N`) into `source.json` `captureStart`. Plain typing is logged without characters.

## Renderer details

- Motion (`DirectorCore/Motion.swift`): `style.motion` picks a `MotionStyle`; the camera and layouts move through `EasedSteps` (explicit eased moves; scale in log space about the zoom's fixed point) except in `classic`, which keeps the windowed `cameraAt`/`layoutAt`. Overlays get an `OverlayPose` from `Motion.pose`; `Scene.animated` draws a posed overlay, blurring it on its own layer when needed.
- Crossfades (`segments[i].transition: "crossfade"`) keep the video's length: a second screen track (`handleTrack` in Composition.swift) carries the next clip's source just before the cut and the previous clip's just after, and `Scene.render` dissolves toward it (`crossfadeMix`). Like every track it's padded to the instruction's end.
- `annotations` rectangles are screen fractions mapped through `screenMap`, so they follow zooms; `blur` ones are applied to the frame in `privacyBlurs` before overlays.
- Animations (`DirectorCore/Animation.swift`, `director/Animate.swift`, `Resources/animations/`): HTML/JS templates rendered by `director animate` with an offscreen WKWebView (init(config) once, seek(t) per frame at 12 fps, snapshots into an H.264 clip in `.animations/`, named by a hash of the data, cues, length and size). WebKit stays out of DirectorCore and the app process; the app runs the bundled `director animate` when a clip is missing (`renderAnimationsIfNeeded`) and won't export until it exists. Rendered clips join `inserts` as full-frame B-roll in `Scene`, after the plan's own, but get their own timeline row and `Selection.animation`. Each template has a `.json` manifest (`AnimationTemplate`: fields, cues, starting data) that the inspector's `AnimationEditor` and the ✦ Animate button are built from. `AnimationSources` finds templates and logos in the video's `animations/` folder, then the personal library, then the bundle; the renderer injects the template's script and passes logos as file URLs. Templates freeze into the video on first use, and `clipPath` hashes the frozen copy, so library changes never touch a finished video. The page code must await WebKit (callAsyncJavaScript, takeSnapshot), never spin the run loop: the CLI's top level is async, so spinning blocks the main queue WebKit calls back on. The `/animate` skill covers adding one.

## Tests

- Every `feat:` or `fix:` commit adds or updates a check in the same commit: `Tests/Checks.swift` for plan, scene and describe logic, `Tests/Playback.swift` for composition tracks, and `smoke-test.sh` for app-only behavior (timeline, inspector, shortcuts, the Claude box). If app behavior can't be checked there, move the logic into DirectorCore, where `test.sh` reaches it. A change with no test says why in a `No test: <why>` line of its commit message. CI enforces this with `macos/check-tests.sh` on every pushed commit that touches `macos/Sources`, `macos/Resources/animations`, `bin/` or `logger/`.
- Before pushing app changes, run `macos/test-all.sh` (lint, checks, playback, animation renders, the sd and logger checks, then the smoke test). CI runs all of it except the smoke test.
- Animation template scripts run in JavaScriptCore in `Checks.swift` (`animationScripts`: the real engine.js and templates against a stand-in page), so template logic like which logos fill the hub's field is checked without WebKit.
- `macos/test.sh` covers the timeline math, planner rules and editing. `test/make-fixture.sh` builds a synthetic project (`projects/fixture`) whose green top bar grows 96 px per source second, so frame mapping can be read off any rendered frame.
- Tests beyond `macos/test.sh`: `macos/playback-test.sh` plays a composition from a synthetic recording through `AVPlayerItemVideoOutput` and fails on black or missing frames (runs in CI). `macos/media-test.sh` (`Tests/Media.swift`, about 50 s, runs in CI) checks the media pipeline on synthetic recordings it draws with CoreGraphics (ffmpeg muxes a test tone): motion sampling, WAV extraction and loudness, `analyze` without audio, Vision screen text under a click, `Join.run` (camera stretched onto the joined clock, every timed file shifted), GIF export, and `Publish.run` without a camera. Transcription (whisper) and the face steps (thumbnails' best faces, face centering, lip sync) need a model or a real face, so only their nothing-found paths run there. `macos/smoke-test.sh` builds dist/, launches that copy on a temp fixture (`-projectsFolder`, `-openProject`), and drives the editor through System Events by PID; it needs a GUI session, so it's local only. `macos/animate-test.sh` renders one animation per bundled template through `director animate` on a temp fixture and fails on a template error, a missing or wrong-length clip, or a blank last frame (about 2 minutes, runs in CI).
- `macos/cli-test.sh` (runs in CI, about 90 s) runs each `director` command and `bin/sd` (help, import, plan, describe) on a temp fixture with a written transcript.json, and checks what they wrote: plan.json edits, rendered sizes and lengths (the video stream, since AAC pads the audio by a varying 0.02-0.2 s), and that bad input fails with a message. Skipped: `upload` (credentials; only its missing-settings error), `analyze` with audio (Whisper; it runs on a silent copy instead), `frame-camera`/`sync-camera` (need a face; only their no-camera errors), `sd record`/`devices`.
- Every composition track must end exactly at the instruction's end. A camera track a few milliseconds long (scaled-range rounding) makes AVPlayer render nothing, black and silent, while `AVAssetImageGenerator` and export still work, so `director still` can't catch it. `buildComposition` trims to the frame count. Test playback with an `AVPlayerItemVideoOutput`, not just stills.
- Spot-check a frame with `macos/.build/release/director still projects/<name> <frame> /tmp/f.png` (`still` writes only inside the project, e.g. `.checks/`, or a temp folder, and never through a symlink).

## Driving the UI

- Driving the UI in tests: timeline bars are accessibility buttons (ordered by position, not by track), so System Events `perform action "AXPress"` selects them; `perform action "AXIncrement"` moves a slider (setting `value` doesn't reach the SwiftUI binding). Always `set frontmost to true` and check it before `keystroke`, or the keys go to whatever app is in front. Use `key code 44` for ⌘/, since `keystroke "/"` is layout-dependent.
- SwiftUI buttons here have no AX title, and timeline bars have no description either. Find inspector and popover buttons by their `.help` text (give a button one if a test needs it) or a timeline chip by its `accessibilityLabel`, and press them with `Tests/AXPress.swift` (`"$AXPRESS" "$PID" help|description <text>`), which walks the test instance by PID. Don't walk AppleScript's `entire contents`: its references name the process, not the PID, so with the installed copy running they reach that copy and fail silently inside `try`. Find a bar by pressing each and reading the inspector. `AXPress` also focuses or reads a text field by placeholder (`focus-field "Ask *"` is the Claude box) and sends a real click to the title bar (`click-title`).
- The smoke test runs AI edits against a stand-in Claude: the app takes `-claudePath <file>` (with `-ai.provider claudeCode`), and the script's stand-in fails like a signed-out Claude or hangs until stopped. The first ask on a recording takes about 10 s to start (screen text is read first). Typing on the Mac while it runs lands in the test instance's Claude box.
- AppleScript `keystroke ","` and `"/"` can map to other keys on non-US keyboard layouts (`","` opened the import panel). Use `key code` or click menu items; the app menu is `menu bar item 2`.

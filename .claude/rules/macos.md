# Swift engine and app (`macos/`)

More detail loads with narrower paths: `macos-app.md` (the app and driving its UI), `macos-renderer.md` (scene, composition, motion, animations) and `macos-tests.md` (what each suite covers).

- `Sources/DirectorCore`: the plan model, mapping and smoothing math (Timeline.swift), draft plan rules (Planner.swift: speech 1x, typing 3x, mouse 1.5x, screen motion 4x, idle and filler words cut, zooms from click/typing clusters; `Rules` holds the thresholds), the readable timeline (Describe.swift), plan problems (PlanCheck.swift, `director validate`), native analysis (motion from decoded frames, whisper-cli → mlx-style transcript.json) and the renderer. `Sources/ScreencastDirector` is the app; `Sources/director` the CLI.
- `Sources/director`: CLI (`director` with no arguments lists the commands). Run it as `bin/director`, which rebuilds it when its sources changed; `macos/.build/release/director` can be stale. The app bundles it, and `Resources/edit-prompt.md` tells headless Claude to use it (`{{DIRECTOR}}` is replaced with its path). A new plan field goes in edit-prompt.md too: `test.sh` fails on a top-level field, or a timed item's field, the prompt doesn't name.
- `director validate` (`PlanCheck.check`): problems by JSON path, including keys the decoder ignored (the file compared with the plan encoded again, `ignoredKeys`), items under `PlanCheck.shortestItem` and describe's WARNING lines; harmless overruns are warnings. Exits 1 on any problem. A new rule for what makes a plan wrong goes in `PlanCheck.check`, or as a describe WARNING. The project's `PostToolUse` hook (`.claude/hooks/check-plan.sh`) runs it after every plan.json edit.
- Agent parity: everything the app does must be doable by an agent. A plan edit is free (the app polls plan.json). A new app action that writes anything else (settings, the support folder, project files, a fresh draft) needs its logic in DirectorCore and a `director` command in the same change. Recording-only actions need an `AppURL` link (`screencastdirector://`, handled in `AppDelegate.handle`). Add the row to the table in `docs/cli.md`. Shared pieces: `AppPreferences` (the app's defaults domain, support folder and Keychain, all overridable in tests through `SD_DEFAULTS_DOMAIN` and `SD_SUPPORT_DIR`), `AppSetting` (what `director settings` may change), `ProfileLibrary`, `FreshDraft`, `PlanCheck` (`director validate`) and `RecordingStatus` (the recorder writes `<support>/recording.json` at each step: `RecordingStatus.post` in Recorder.swift; `director status` reads it). A new UserDefaults key fails `settingsDriftCheck` (Tests/ChecksFiles.swift) until it's in `AppSetting.all` or that check's not-for-agents list. Settings objects re-read their keys when the app comes to the front (`AppDelegate.reloadSettings`): give a new one a `reload()` that writes nothing back (the `loading` guard, `syncSetting`).
- Command Line Tools only: no Xcode, so no SwiftUI macros (`@State`) and no XCTest. SourceKit reports "Cannot find type ... in scope" on single files; ignore it and trust `swift build`.
- Editor actions (`DirectorCore/EditorActions.swift`): `Selection` and `TimelineSelection` (click and drag-box rules), and the plan edits behind the timeline, keyboard and transcript (delete, group moves, clip speed, zoom nudge and duplicate, marker jumps, word selection, the AI ask's context). `ProjectModel` keeps the app state (published selection, playhead, undo, status) and calls these, so `test.sh` checks them (`Tests/ChecksEditor.swift`). Put new plan logic for an editor action there, not in ProjectModel.
- Profiles (`DirectorCore/Look.swift`, `Formats.swift`): `plan.look` holds fonts, colors, the bracket frame and the watermark; `style.screenAspect` crops the screen for vertical, square and feed formats, and `Scene.screenMap` pans the crop to the camera focus (the last click when there's no zoom).
- Lip sync (`DirectorCore/LipSync.swift`): the recorder's `camera.offset` comes from first-frame timestamps, which webcams can stamp hundreds of ms late. `LipSync.measure` correlates Vision inner-lip opening with voice level in four 30 s speech windows, searching only ±0.5 s around the current offset (speech rhythm repeats the correlation about every 0.7 s). It runs in `analyzeAndPlan`, `director sync-camera` and Camera > Lip sync.
- Publishing (`DirectorCore/Publish*.swift`: text, faces, covers): the SRT uses the same caption pages as the burned-in captions. Thumbnails score camera frames with `VNDetectFaceCaptureQualityRequest` plus `CIDetector` smile and blink detection, and cut the person out with `VNGeneratePersonSegmentationRequest`.
- Pausing doesn't stop the writer: the paused stretch is recorded, saved as `source.json` `pauses` (source seconds), cut by the planner, and kept cut by `retrimPauses(paused:)`. `InputTap.paused` stops input logging meanwhile.
- Secrets (`DirectorCore/Secrets.swift`, `director secrets`): full-frame Vision OCR every second where `motion.json` shows a change (mean pixel change over 0.02; a few typed characters), matched against key, password and email patterns; secrets.json stores them masked. A finding runs from the sample before it to the sample after, since it may appear anywhere between. Its blur cuts in and out (`none` motion), since a 0.2 s fade shows the text. Describe WARNs about findings in kept segments no blur covers. Vision's box for part of a line runs a word early, which only widens the blur.
- Provenance (`DirectorCore/Provenance.swift`): `export()` writes the app version, date and rendered plan into the MP4 under a private iTunes key (`sdpv`): an MP4 export drops QuickTime metadata keys, and the comment field would show the JSON in Finder. `director provenance` reads it.
- Input log (`events.jsonl`): `InputTap` (the app's event tap) writes what `DirectorCore/InputEvents.swift` records for each event, checked with synthetic events in `Tests/ChecksInput.swift` and read back through `Project.loadEvents`. Timestamps use `CLOCK_UPTIME_RAW`, the host clock ScreenCaptureKit stamps frames with; the recorder writes the first frame's time to `source.json` `captureStart`. Plain typing is logged without characters.

## Tests

- Every `feat:` or `fix:` commit adds or updates a check in the same commit: `Tests/Checks*.swift` for plan, scene and describe logic, `Tests/Playback.swift` for composition tracks, and `smoke-test.sh` for app-only behavior (timeline, inspector, shortcuts, the Claude box). If app behavior can't be checked there, move the logic into DirectorCore, where `test.sh` reaches it. A change with no test says why in a `No test: <why>` line of its commit message. CI enforces this with `macos/check-tests.sh` on every pushed commit that touches `macos/Sources`, `macos/Resources/animations` or `bin/`.
- Before pushing app changes, run `macos/test-all.sh` (lint, checks, playback, media, the CLI and sd, animation renders, then the smoke test). CI runs `test-all.sh --no-smoke`, so a new suite goes in test-all's list only. After pushing, watch the CI run until it passes (`gh run watch <id> --exit-status`; the project's `after-push.sh` hook says so too): CI's compiler has rejected code that built locally.
- Spot-check a frame with `bin/director still projects/<name> <frame> /tmp/f.png` (`still` writes only inside the project, e.g. `.checks/`, or a temp folder, and never through a symlink). See the editor with `macos/app-shot.sh <project-dir> <out.png>`.
